# Vulcan Brain 飞书功能闭环审计

## 审计目的
确保每个功能都具备完整的用户体验闭环，不遗漏关键通知和交互。

---

## 功能闭环检查模板

每个功能需要检查以下环节：

```
1. 触发入口 - 用户如何启动这个功能？
2. 数据处理 - 系统做了什么？
3. 状态持久化 - 数据保存在哪里？
4. 发起方反馈 - 发起人收到什么确认？
5. 相关方通知 - 相关人员收到什么通知？
6. 后续操作入口 - 如何进行下一步？
7. 结果反馈 - 操作完成后谁需要知道？
8. 异常处理 - 出错时用户知道吗？
```

## 七、整体架构建议

### 7.1 通知中心设计

建议创建统一的通知服务，所有功能模块调用同一接口：

```python
class NotificationService:
    async def notify_user(user_id, title, content, card=None):
        """统一发送通知给用户"""

    async def notify_pm(title, content, card=None):
        """通知 PM (Tony)"""

    async def notify_task_assignee(task, event_type):
        """任务相关通知"""

    async def notify_approval_parties(approval, event_type):
        """审批相关通知"""
```

### 7.2 功能清单维护

建议维护功能清单表：

| 功能ID | 功能名 | 触发方式 | 通知对象 | 状态 |

| APR-01 | 发起审批 | 菜单 | 申请人+审批人 | ✅ |
| APR-02 | 处理审批 | 卡片 | 申请人+审批人 | ✅ |
| TSK-01 | 分配任务 | Web | 被分配人 | ⚠️ |
| TSK-02 | 接受任务 | 卡片 | PM | ⚠️ |
| ... | ... | ... | ... | ... |
