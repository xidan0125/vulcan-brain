# 企业人才图谱 - 产品设计文档

> 融合方案: Gemini GraphRAG + 职能驱动架构

## 一、设计来源

本设计融合了两个独立方案的优势：

| 来源 | 核心贡献 |
|------|----------|
| **Gemini 方案** | GraphRAG 双引擎架构、ONA 指标体系、风险算法、星系图可视化 |
| **Claude 方案** | 职能驱动架构、分层导航、管理者视角、可插拔算法设计 |

**融合策略**:
1. 用 Gemini 的算法指标设计 (Hub/Bridge/Burnout)
2. 用 Claude 的职能驱动架构和分层导航
3. 网络图作为"探索模式"，职能卡片作为"管理模式"

---

## 二、用户与场景

### 2.1 目标用户

| 用户角色 | 核心需求 | 使用场景 |
|----------|----------|----------|
| **CEO/高管** | 全局视野：组织健康、关键依赖、风险预警 | 周会/月会决策参考 |
| **HR 总监** | 人才盘点：能力分布、发展建议、离职预警 | 人才规划、绩效评估 |
| **部门负责人** | 团队洞察：协作效率、工作分配、倦怠风险 | 日常管理 |
| **BD/销售负责人** | 外部关系：客户触达、关系集中度 | 客户管理 |

### 2.2 核心场景

**场景1: 组织健康检查 (CEO)**
> "公司现在有哪些职能？每个职能谁在负责？有没有单点风险？"

**场景2: 关键人物识别 (HR)**
> "谁是公司最关键的人？如果他离职会影响什么？"

**场景3: 倦怠预警 (部门负责人)**
> "我团队里谁可能工作量过大？需要关注谁？"

**场景4: 客户关系审计 (BD)**
> "我们和客户A的关系由谁维护？有没有只有一个人对接的风险？"

## 五、数据指标体系

### 5.1 人员指标

| 指标名称 | 计算方式 | 业务含义 |
|----------|----------|----------|
| `hub_score` | Degree Centrality (归一化) | 信息吞吐量，值越高越是枢纽 |
| `bridge_score` | Betweenness Centrality | 跨领域连接能力，值越高越是桥梁 |
| `external_reach` | 唯一外部域名数 | 外部资源触达能力 |
| `influence_score` | PageRank | 综合影响力 |
| `burnout_index` | 非工作时间邮件占比 | 倦怠风险 |
| `overload_index` | 收件量/发件量 | 工作负载 |

### 5.2 职能指标

| 指标名称 | 计算方式 | 业务含义 |
|----------|----------|----------|
| `coverage_score` | 人员数 × 平均贡献度 | 职能覆盖充足度 |
| `single_point_risk` | 核心人员数 == 1 | 单点故障风险 |
| `knowledge_concentration` | TOP1 贡献度 / 总贡献度 | 知识集中度 |

### 5.3 关系指标

| 指标名称 | 计算方式 | 业务含义 |
|----------|----------|----------|
| `interaction_volume` | 双向邮件总数 | 关系强度 |
| `symmetry_ratio` | min/max 方向邮件数 | 沟通对称性 |
| `relationship_type` | AI 分类 | 关系性质 |

## 六、技术实现要点

### 6.1 API 设计

```
# 概览
GET /api/talent-graph/overview
返回: 健康分数、TOP人物、风险预警

# 职能
GET /api/talent-graph/functions
返回: 职能列表 + 负责人 + 风险等级

GET /api/talent-graph/functions/{id}
返回: 职能详情 + 成员 + 主题

# 人员
GET /api/talent-graph/persons
参数: sort_by (hub|bridge|external|risk)
返回: 人员排行榜

GET /api/talent-graph/persons/{email}
返回: 人员详情 + 指标 + 关系 + 风险

# 风险
GET /api/talent-graph/risks
返回: 按类型分组的风险列表

# 网络图
GET /api/talent-graph/network
参数: include_external, min_weight
返回: nodes[], edges[] (for D3/Force Graph)

# 重建
POST /api/talent-graph/rebuild
触发: 重新运行所有算法
```

### 6.2 前端组件

```
components/
├── TalentGraphDashboard.tsx      # 概览仪表盘

├── RiskRadar.tsx                 # 风险雷达

    ├── RiskBadge.tsx             # 风险徽章
    └── PersonCard.tsx            # 人员卡片
```

### 6.3 数据更新策略

```
触发时机:
1. 每日凌晨自动重建 (cron)
2. 新邮件同步后增量更新
3. 手动触发重建

增量更新范围:
- 基础统计 (发件量、互动对): 实时更新
- 网络指标 (中心度、社区): 每日重算
- AI 语义 (关系类型、主题): 按需更新
```
