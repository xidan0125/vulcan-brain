## 项目背景

我们正在构建一个**企业人才图谱系统**，基于公司邮件数据分析组织内的人才分布、协作关系、影响力和风险。

**核心理念**：从企业管理的第一性原理出发，以"职能"为核心组织视角，而非传统的以"人"为中心。

## 需要解决的问题

### 核心问题 (CEO/管理者视角)

1. **职能覆盖**: 公司有哪些核心职能？谁在负责？有没有人员缺口？
2. **关键依赖**: 谁是不可或缺的人？如果他离开会影响什么？
3. **协作健康**: 团队协作是否健康？有没有信息孤岛？
4. **外部关系**: 谁维护着重要的客户/供应商关系？有没有集中风险？
5. **风险预警**: 谁可能倦怠？谁可能离职？哪里有单点故障？

### 现有系统的问题

我们之前用 AI 直接分析邮件内容生成个人画像，但存在严重问题：

**案例**: David 是公司发邮件最多的人(#1)、连接303个外部组织(#1)、与核心人物都有强互动，但 AI 生成的画像只写了"技术协调员，处理某个项目的成本分摊"——完全没有识别出他的战略重要性。

**问题根源**:
- 只分析了文本内容，没有做网络结构分析
- 没有量化指标（中心度、桥梁度等）
- 以人为单位独立分析，没有全局对比

## 期望的算法设计

请帮我设计一套**可插拔的算法体系**，用于构建企业人才图谱。

### 设计要求

1. **分层架构**: 不同层次的问题用不同的算法解决
2. **硬指标优先**: 先计算可验证的数学指标，再用AI做语义增强
3. **可扩展性**: 新算法可以方便地加入，不需要改动核心架构
4. **可解释性**: 每个指标都要有清晰的业务含义

### 需要覆盖的分析维度

| 维度 | 核心问题 | 期望算法 |
|------|----------|----------|
| 网络拓扑 | 谁是信息枢纽？谁是桥梁？ | 中心度、社区发现等 |
| 关系语义 | 关系是什么类型？健康吗？ | 分类、情感分析等 |
| 职能映射 | 每个人属于什么职能？ | 主题聚类、映射等 |
| 外部生态 | 外部关系由谁维护？ | 分类、集中度分析等 |
| 风险预警 | 有什么隐患？ | 倦怠、离职、单点故障等 |

### 期望输出

1. **算法清单**: 每个维度需要哪些算法？
2. **算法原理**: 每个算法的数学原理或逻辑
3. **输入输出**: 算法需要什么数据？输出什么指标？
4. **业务解释**: 每个指标的业务含义是什么？
5. **优先级建议**: 哪些算法最重要应该先做？
6. **技术选型**: 推荐使用什么库/工具？

## 技术约束

- **语言**: Python
- **图计算**: 优先考虑 NetworkX (节点数 <1000，内存计算足够)
- **存储**: MongoDB
- **AI**: 本地 Qwen3 (批量处理) + 云端 Gemini (高层洞察)
- **前端**: Next.js (需要返回 JSON 供前端渲染)
